Part 2 — Concept Map by Week

Week 1 — Algorithms, expressions and types

  • Type rules — the whole of W1 in five lines:
  • int op int → int, except / (always float) and ** with a negative exponent (2**-3 → 0.125, a float).
  • int op float → float. Any float anywhere in the expression poisons the result to float: 7.0 // 2 → 3.0, not 3.
  • A quoted literal is str even when it looks like a number: "7" + "2" is "72", not 9.
  • + joins str with str only. "a" + 1 → TypeError. "ab" * 3 → "ababab" (str × int is legal).
  • int(), str(), float(), len() change the type before the next operator sees it — that's the point of the question.
  • // and %: // floors, % keeps the remainder. The classic decomposition: years = n // 365, weeks = (n % 365) // 7, days = (n % 365) % 7.
  • ⚠️ // floors toward −∞, it does not truncate: -7 // 2 is -4, not -3. And % takes the sign of the divisor: -7 % 2 is 1, not -1.
  • String slicing: s[a:b] includes a, excludes b → length b − a (clipped at the ends). s[:k] is the first k characters. Count spaces you concatenate in — they're characters too.
  • f-strings with a width: f"{5:3}" pads to 3 columns → " 5" (two spaces). The width is part of the output length.
  • Work inside-out. Every W1 question is one expression. Evaluate the innermost call first, note its type, then apply the next operator to that.

Week 2 — Conditionals (single branch)

  • Chained comparison: a < b < c means (a < b) and (b < c) — and b is evaluated only once. The result is bool.
  • bool is an int: True == 1, False == 0, True + True == 2. So type(1 < 2) is bool, but (1 < 2) + 1 is 2, an int. A comparison stays bool unless an arithmetic operator is applied afterwards.
  • Single if/else tracing: substitute the inputs, follow exactly one branch, print. Write the variable values in the margin — don't do it in your head.
  • The unassigned-variable trap: if a name is assigned only inside an if body and then used after the block, the code raises NameError exactly when every guarding condition is False. The question is almost always "for which inputs does this error?" — answer: the inputs that satisfy none of the conditions.

Week 3 — Conditionals continued (the half of the paper)

  • Operator precedence — memorize cold: comparisons (<, ==, …) → not → and → or.
  • So not True and False is (not True) and False = False.
  • And True or False and False is True or (False and False) = True.
  • Parenthesise mentally before you substitute, then reduce innermost first.
  • For "deduce the variable" questions: not not x is x — undo not by not.
  • if/elif/else chains: the FIRST true condition runs, every later one is skipped. This is the single most-tested fact in the course.
  • Separate ifs vs elif — the difference that the MSQs live on:
  • Separate ifs are each tested independently → several can fire, or none. Output can print twice.
  • elif/else makes branches mutually exclusive → exactly one fires (with an else), at most one (without).
  • To find where two versions differ: look for an input that satisfies two conditions at once. That input is the answer.
  • "Which inputs give output X" questions: write down the interval each branch actually owns, remembering that earlier conditions carve out later ones. if x > 10 then elif x > 5 means the second branch owns 5 < x <= 10, not x > 5. Then test boundary values explicitly: the threshold itself, and ±1.
  • Counting inputs: for a nested-range question ("how many integer pairs print Yes"), count integers in the rectangle/interval inclusive of both ends — a <= x <= b has b − a + 1 integers.
  • Truthiness: falsy values are 0, 0.0, "", [], {}, (), None. Everything else is truthy — including "0", " ", "False", -1, and [0].
  • Short-circuit returns the operand, not a bool:
  • a or b → the first truthy operand (or the last one if all falsy): 0 or "x" is "x", 3 or 5 is 3.
  • a and b → the first falsy operand (or the last one if all truthy): "" and 5 is "", 3 and 5 is 5.
  • isinstance: isinstance(True, int) is True (bool subclasses int) but isinstance(1, bool) is False. This asymmetry is the whole point of the two hardest questions in the pool.
  • Bitwise &/| are not and/or: they operate on the integer bits — 5 & 3 is 1. On two bools they do behave like logical ops (True & False is False) and return bool, but they do not short-circuit and they bind tighter than comparisons would suggest. If you see & or |, slow down.
  • return inside an if exits the function immediately — nothing after it in the function runs, including later elifs.
  • "Choose the snippet that is correct" questions: don't read for elegance, test each candidate with the nasty inputs — equal values (ties), exactly on the threshold, and a negative. The bugs planted are always one of: independent ifs printing twice, an elif chain in the wrong order, > where >= is needed, or a missing else.

Week 4 — Iterations and ranges

  • range(start, stop, step) excludes stop. range(1, 11) yields 10 values, 1 through 10. range(10, 0, -2) yields 10, 8, 6, 4, 2. Number of values = ceil((stop − start) / step).
  • "First hundred powers of two" means 100 iterations, with the multiplier updated every pass. Check three things on every candidate loop: the first value printed, the last value printed, and the number of iterations. One of the distractors is always off by one at exactly one of those three.

  • The digit-extraction skeleton — this is 9 questions: python while n > 0: d = n % 10 # peel the last digit # <<< the only line that changes between questions >>> n = n // 10 # drop it What sits in the middle is sum (s += d), product (p *= d), reverse (r = r*10 + d), positional weight (t += d * w; w *= 10), or a filter (if d % 2: s += d).

  • ⚠️ Start the accumulator at the identity: 0 for a sum, 1 for a product. A product started at 0 returns 0 for every input — that is the standard planted trap, and Q1 2023 Jul Q11 is exactly it.

  • ⚠️ while n > 0 means input 0 runs the body zero times → you get the accumulator's initial value back.
  • ⚠️ Digit loops assume a positive n. On a negative input the loop body never runs.
  • while-loop tracing — do not do it in your head. Make a table, one row per iteration, one column per variable, plus a column for the condition's truth value. Stop when the condition first fails.
  • "Final value of the loop variable" = the first value that violates the condition, not the last one that satisfied it.
  • "Iteration count" = the number of rows in your table. Count rows, don't estimate.
  • Two-pointer loop: i starts at the left end, j at the right end, and you compare a[i] + a[j] with the target:
  • sum too big → j -= 1 (shrink from the right)
  • sum too small → i += 1 (grow from the left)
  • loop runs while i < j; when the pointers cross, nothing was found → returns None/False. The "for which arguments does it return None" question is asking you to find the input with no valid pair.
  • Fibonacci-style loops (a, b = b, a + b): the simultaneous assignment uses the old values of both on the right-hand side. Write both variables per row or you will get it wrong.

Python Quiz 1 — Must-Know List (read this last, right before you walk in)

One screen. No new material — just the things that show up in nearly every paper and the places this exam takes marks off people who actually know Python.

Highest-probability topics (weeks 1–4, 70 questions across 19 papers)

  1. if/elif/else tracing + "which inputs give output X" — 16 questions, the biggest cluster in the course.
  2. Digit extraction loops (% 10, // 10) — 9 questions.
  3. Boolean expression evaluation (not/and/or precedence) — 8 questions.
  4. Separate ifs vs elif — 5 questions, nearly always MSQ.
  5. Truthiness / isinstance / short-circuit — 5 questions, including both difficulty-4 questions on record.

W3 + W4 are 84% of the marks. If time runs out, W1 and W2 are what you drop.

The 10 traps that cost the most marks

  1. Precedence is not → and → or. not True and False is (not True) and False = False. True or False and False is True. Parenthesise on paper before substituting.
  2. In an elif chain the FIRST true condition wins and the rest are skipped. Separate ifs are each tested independently — several can fire, or none. The exam's favourite MSQ is an input that satisfies two conditions, because that's the only place the two versions differ.
  3. Earlier conditions carve out later ones. if x > 10 / elif x > 5 means branch two owns 5 < x <= 10, not x > 5. Always test the threshold itself and ±1.
  4. Accumulator identity: 0 for a sum, 1 for a product. A product started at 0 returns 0 for every input — that's the planted bug, and it's an exam question twice.
  5. while n > 0 never runs on input 0 — you get the initial accumulator value straight back.
  6. Falsy is exactly 0, 0.0, "", [], {}, (), None. "0", " ", "False", -1 and [0] are all truthy.
  7. a or b returns the first truthy operand, a and b the first falsy one — not a bool. 0 or "x" is "x". 3 and 5 is 5.
  8. isinstance(True, int) is True, but isinstance(1, bool) is False. That asymmetry is the whole content of the two hardest questions in the pool.
  9. / always returns a float, even 4/2. And // floors toward −∞ (-7 // 2 is -4, not -3), while % takes the sign of the divisor (-7 % 2 is 1).
  10. range(a, b) excludes b → range(1, 11) is ten values. The "final value of the loop variable" is the first value that breaks the condition, not the last one that passed.

The two rules that matter more than any fact above

  • Make the table. Every while question: one row per iteration, one column per variable, plus the condition's truth value. Stop when it first fails. Never trace a loop in your head — that is where the marks actually go.
  • Test the boundaries. For every "choose the correct snippet" question, run each candidate on the tie (equal values), the exact threshold, and a negative. The four planted bugs are always: independent ifs printing twice, an elif chain in the wrong order, > where >= was needed, or a missing else.

Last check before you open the paper

  • return inside an if exits the function — later elifs never run.
  • A variable assigned only inside an if raises NameError exactly when every condition is False.
  • & and | are bitwise, not logical: 5 & 3 is 1. If you see them, slow down.
  • SA answers are exact numeric entry — do the arithmetic once carefully rather than twice fast.
  • Read every MSQ option word by word. Most wrong options are one flipped token from correct (if↔elif, >↔>=, and↔or, //↔/).

Part 2 — Concept Map by Week

Week 1 — Foundations of Data

  • Statistics: "the art of learning from data" (collection → description → analysis → conclusions).
  • Descriptive vs. inferential: descriptive = summarize; inferential = generalize from sample to population (needs probability). A study on a sample can still be purely descriptive if you don't generalize beyond it.
  • Population vs. sample: sample must be representative — missing an entire subgroup breaks representativeness even if it's technically a subset.
  • Data: facts/figures collected & summarized; doesn't "speak" by itself. Comments, likes, multimedia all count as data.
  • Structured vs. unstructured data: structured = organized rows/columns; unstructured = scattered, no context.
  • Variables & cases (tidy data rules): each variable → one column; each case → one row; consistent unit per variable column. A column constant across all cases is not a variable.
  • Missing (NA) ≠ 0: a bowler who never bowled → NA; a bowler who bowled and took 0 wickets → 0. Don't conflate.
  • Categorical vs. numerical: categorical = group membership (gender, blood group); numerical = has measurement units (marks, height). Gotcha: jersey number / mobile number look numeric but are categorical (arithmetic on them is meaningless).
  • Discrete vs. continuous (numerical only): discrete = whole-number counts; continuous = any fractional value.
  • Measurement units: must be consistent across all observations of a variable (don't mix cm and feet).
  • Cross-sectional vs. time series: time series = same variable tracked over time (→ timeplot); cross-sectional = observed at one point in time.
  • Scales of measurement (the single most-tested Week 1 concept):
  • Nominal: labels only, no order (gender, blood group, jersey number).
  • Ordinal: labels + order, but unequal/undefined gaps between ranks (poor/good/excellent).
  • Interval: order + meaningful differences (subtraction valid), but no true zero → ratios meaningless. Classic example: °C/°F — 40°C is not twice as hot as 20°C (only Kelvin has an absolute zero).
  • Ratio: interval + true zero → ratios are meaningful; full arithmetic valid (height, weight, marks, runs). 300 runs really is twice 150 runs.
  • Categorical data → nominal/ordinal only. Numerical data → interval/ratio only.

Week 2 — Describing Categorical Data (single variable)

  • Frequency distribution: count per distinct category. Relative frequency = frequency ÷ total n; always sums to 1 (used to compare datasets of different sizes).
  • Pie chart: wedge angle = relative frequency × 360°. Shows share of a whole. Avoid exploding/3D slices.
  • Bar chart: bar height = frequency; bars equal width, not touching. Shows comparison across groups, not proportions of a whole.
  • Pareto chart: bar chart sorted by frequency (descending) — but only valid for nominal data. If the variable is ordinal (e.g., S/M/L), you must keep the natural order instead of sorting by frequency.
  • Area principle: area shown must be proportional to the data it represents. Violations: decorated graphics (icons of uneven size) and truncated graphs (non-zero baseline exaggerates differences) — if you must truncate, explicitly mark the axis break.
  • Round-off errors: individually-rounded percentages may not sum to exactly 100% — always check totals (matters for pie chart degrees summing to 360°).
  • Mode: highest-frequency category; works for nominal and ordinal. Can be bimodal/multimodal.
  • Median (ordinal data only): middle value once ranked; undefined for nominal data. Mode ≠ median in general — mode = most frequent, median = middle-ranked; they need not coincide.
  • Best practice: use "Other" bucket for many small categories instead of silently dropping them; always label axes/title/legend.

Week 3 — Describing Numerical Data (the calculation-heavy core)

  • Frequency tables: discrete data with few distinct values → one class per value. Continuous data → grouped into classes (5–20 classes, rule of thumb); convention: interval includes its left end, excludes its right end (e.g., "30–40" includes 30, not 40).
  • Histogram: bars touch (no gaps) since data is continuous — this is the key visual difference from a bar chart.
  • Stem-and-leaf plot: stem = all digits except last, leaf = last digit; leaves sorted ascending within each stem row. Retains actual values (unlike histogram).
  • Mean: x̄ = Σx/n (sample), μ = Σx/N (population). Grouped discrete: x̄ = Σfᵢxᵢ/n (exact). Grouped continuous: x̄ = Σfᵢmᵢ/n using class midpoints (approximation only).
  • ⚠️ Mean is highly sensitive to outliers.
  • Median: middle of sorted data. n odd → the ((n+1)/2)-th value. n even → average of the two middle values.
  • ⚠️ Median is NOT sensitive to outliers.
  • Mode: most frequent value; may not exist, may be multiple.
  • Transformation rules (memorize this table cold — tested constantly):
Transform yᵢ = xᵢ + c Transform yᵢ = xᵢ × c
Mean: ȳ = x̄ + c Mean: ȳ = x̄ × c
Median: +c Median: ×c
Mode: +c Mode: ×c
Variance: unchanged Variance: × c²
SD: unchanged SD: × c (not c²)
  • Why dispersion measures matter: {3,3,3,3,3} and {1,2,3,4,5} have identical mean/median/mode but obviously different spread.
  • Range = Max − Min. Extremely outlier-sensitive (uses only 2 points).
  • Variance: uses all points, squared deviations from the mean.
  • Population: σ² = Σ(xᵢ−μ)²/N
  • Sample: s² = Σ(xᵢ−x̄)²/(n−1) ← don't forget n−1 for sample variance.
  • SD = √variance. Restores original units (variance has squared units).
  • Percentiles — two different valid algorithms give different answers, know both:
  • Manual: sort data; compute n·p. If not integer → round up, take that ranked value. If integer → average that rank and the next.
  • Google Sheets PERCENTILE(): rank = p(n−1)+1; interpolate between the integer and fractional parts.
  • Quartiles: Q1 = 25th pct, Q2 = median, Q3 = 75th pct. Five-number summary: Min, Q1, Q2, Q3, Max.
  • IQR = Q3 − Q1. More outlier-robust than range/SD.

Week 4 — Association Between Two Variables

  • Association ≠ causality — course only ever claims association.
  • Contingency table: rows/columns = category levels, cells = counts, margins = row/column totals. Preserve natural order for ordinal variables (don't let software alphabetize).
  • Row/column relative frequency: divide cell by its row (or column) total.
  • Rule: if relative frequencies are ~same across all rows → no association. If they differ noticeably → associated. (Row-wise and column-wise checks agree.)
  • Stacked bar chart (raw counts) vs. 100% stacked bar chart (normalized proportions — best for comparing shares across groups).
  • Scatter plot: explanatory variable (x) vs. response variable (y). Describe using D-C-V-O: Direction, Curvature, Variation, Outliers. Course only quantifies linear association.
  • Covariance: Cov(x,y) = Σ(xᵢ−x̄)(yᵢ−ȳ)/(n−1) [sample] or /N [population]. Sign tells direction; magnitude hard to interpret (has mixed units).
  • Correlation (Pearson's r) = Cov(x,y)/(sₓ·sᵥ). Unitless, always in [−1, +1]. |r| near 1 → strong linear association; near 0 → weak/none. Sign = direction, doesn't depend on axis choice.
  • Best-fit line: y = mx + c. Sign of slope m = direction. R² = r² (proportion of variance explained); R² tells fit strength, not direction.

  • Point bi-serial correlation (numerical variable X vs. dichotomous categorical Y, coded 0/1): rpb = (Ȳ₀ − Ȳ₁)/sₓ × √(p₀p₁) — split by group, use group means and group proportions.

  • ⚠️ Sign flips if you swap which category is coded 0 vs 1 — only |rpb| indicates strength.

  • Line-fitting doesn't apply here (x only takes two values).

Stat 1 — Must-Know List (read this last, right before you walk in)

One screen. No new material, no derivations — just the things that show up in nearly every paper and are the most common places to lose an otherwise-easy mark.

Highest-probability topics (appear in 8-9 of 9 papers)

  1. Descriptive vs. inferential + population vs. sample
  2. Scales of measurement (nominal/ordinal/interval/ratio) + data types
  3. Mean/median/mode + transformation effects (+c, ×c)
  4. Variance & SD (population vs sample) + transformation effects

The 8 traps that cost the most marks (from every paper reviewed)

  1. Sample variance uses n−1, population variance uses n. Mixing these up is the single most common silent error.
  2. Transformation rules — memorize cold: - +c: mean/median/mode shift by c · variance & SD unchanged - ×c: mean/median/mode scale by c · variance scales by c² · SD scales by c (not c²)
  3. Percentile rule: sort → compute n·p → not integer = round up, take that rank → integer = average that rank and the next.
  4. "Sample" ≠ automatically inferential. A study is only inferential if it generalizes BEYOND the sample to a larger population. Analyzing the sample itself = descriptive.
  5. Interval vs ratio: the only question that matters is "does zero mean true absence, and are ratios meaningful?" (40°C isn't twice 20°C — no true zero → interval. 300 runs is twice 150 runs — true zero → ratio.)
  6. Mode works on nominal data; median does NOT (median needs order, nominal has none). This nominal/ordinal swap is the most repeated wrong-option trap across every paper.
  7. Mean is never valid for categorical data — only mode (any categorical) and median (ordinal only). "Mean, median, mode can all summarize a categorical variable" is a recurring false MSQ option.
  8. y = x + c always gives correlation r = 1 (or −1 for y = −x + c) — don't recompute, just recognize the shape.
