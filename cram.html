W1

Data types & scales

0/3 learned · 21 marks

Week overview

Week 1 is the vocabulary of the whole course: what data is, how a dataset is laid out, what kind of variable each column holds, and which scale of measurement it sits on.

It looks easy, and it is where marks leak. The scale decides which summaries are allowed (mode, median, mean) and which charts make sense, so every later week leans on this one. Quiz questions are classification MCQs and MSQs where one option is subtly wrong.

After this week you can:

  • Classify any variable as categorical or numerical, and numerical ones as discrete or continuous
  • Place a variable on the nominal / ordinal / interval / ratio ladder and say what that permits
  • Tell cross-sectional data from time-series data
  • Tell a descriptive statement from an inferential one

About 12 min to read · 4 practice problems at the end

1.1Data, cases and variables

Statistics is learning from data: you collect it, describe it, analyse it, and conclude something. Data is anything recorded — numbers, text, likes, images.

A dataset is structured when it sits in rows and columns, and unstructured when it has no fixed shape (a pile of tweets, photos). The course works with structured data.

In a well-organised (“tidy”) table:

  • each row is one case (one student, one match, one patient);
  • each column is one variable — a characteristic that varies across cases;
  • each column uses one unit throughout (never mix cm and feet).

A column with the same value for every case is not a variable — nothing varies.

Missing is not zero

A bowler who never bowled has wickets = NA (not applicable / missing).
A bowler who bowled and took none has wickets = 0.

Writing 0 for NA drags the mean down and changes the count of cases.

How the exam asks it: “Which of these is a variable in this table?” or “how many cases?” with a constant column or a missing value planted in it.

1.2Categorical vs numerical, discrete vs continuous

A categorical variable records which group a case belongs to: blood group, city, grade, shirt size. A numerical variable records a measured or counted quantity, usually with units: height in cm, runs, income in ₹.

The trap is variables that look numeric but are labels: jersey number, roll number, PIN code, mobile number, patient ID. Averaging them is meaningless, so they are categorical.

Numerical variables split once more:

  • Discrete — counts; only whole-number values. Number of siblings, goals, students in a class.
  • Continuous — measurements; any value in a range, including fractions. Height, time taken, temperature.
Two questions that settle it

1. Does averaging it make sense? No → categorical.
2. If numerical: is it counted or measured? Counted → discrete, measured → continuous.

1.4Cross-sectional vs time-series data

Cross-sectional data observes many units at one point in time: marks of 200 students in this quiz, prices of 50 stocks on 1 Jan.

Time-series data follows one variable over successive time points: one stock's closing price every day of 2025, India's yearly GDP. It is plotted as a line over time (a timeplot).

Worked example

“Daily closing price of Infosys through 2025” → time series.
“Closing prices of the 50 Nifty stocks on 1 Jan 2025” → cross-sectional.

1.5Descriptive vs inferential statistics

Descriptive statistics summarises the data you actually have — tables, charts, averages of those cases.

Inferential statistics uses a sample to make a claim about a larger population. Because the sample could have come out differently, inference needs probability and carries sampling error.

The test is not whether a sample was used. It is whether the claim leaves the data that was collected.

Trigger words for inferential

generalise · population · estimate · predict · sampling error · test a claim · “all students” when only some were asked

Recap — read this the night before

  • Case / variable — row / column; a constant column is not a variable
  • NA ≠ 0 — missing is not the same as a measured zero
  • Categorical — group labels, including numeric-looking IDs
  • Discrete / continuous — counted / measured
  • Nominal → ordinal → interval → ratio — each adds order, then equal gaps, then a true zero
  • Interval vs ratio — does zero mean none? °C no (interval), kg yes (ratio)
  • Valid centres — nominal: mode · ordinal: + median · numerical: + mean
  • Descriptive vs inferential — does the claim reach beyond the cases measured?

Traps that cost marks

  1. A sample does not make it inferential. Analysing the sample and stopping there is descriptive. It is inferential only when the claim reaches beyond the sample.
  2. Interval vs ratio turns on one question: does zero mean true absence, so that ratios mean something? 40°C is not twice 20°C → interval. 300 runs is twice 150 → ratio.
  3. Mode works on nominal, median does not. Median needs order; nominal has none.
  4. Mean is never valid for categorical data. “Mean, median and mode can all summarise a categorical variable” is a recurring false MSQ option.
  5. Numeric-looking identifiers are categorical. Jersey number, PIN code, room number — the average of them is meaningless.
  6. Calendar year is interval, age is ratio. Year 0 is an arbitrary starting point; age 0 is a real zero.

W2

Charts & frequency

0/4 learned · 11 marks

Week overview

Week 2 describes one categorical variable. There are three moves: tabulate it (frequency table), picture it (bar, pie or Pareto chart), and summarise it (mode, and median if it is ordinal).

The quiz questions are mostly arithmetic on a chart — turning pie percentages into amounts, reading a relative frequency off a bar chart — plus true/false statements that test whether you know which chart and which summary suits which kind of variable.

After this week you can:

  • Build a frequency and relative-frequency table and check it
  • Convert between counts, relative frequencies, percentages and pie-chart angles
  • Choose between bar, pie and Pareto charts, and spot a misleading chart
  • Find the mode of any categorical variable and the median of an ordinal one

About 12 min to read · 4 practice problems at the end

2.1Frequency tables

List each distinct category once and count how many cases fall in it. That count is the frequency f.

The relative frequency is the share of all cases: f ÷ n. Relative frequencies always add to 1 (or 100%). Use them whenever you compare two groups of different sizes — 30 out of 50 and 30 out of 200 are the same count but very different shares.

For an ordinal variable keep the categories in their natural order (S, M, L, XL), and you can add a cumulative frequency column — you need it for the median.

Formulas

relative frequency = f / n
percentage = 100 × f / n
Σ f = n,   Σ relative frequency = 1

2.2Bar charts and Pareto charts

A bar chart draws one bar per category, height = frequency (or relative frequency). Bars have equal width and do not touch — the gaps say these are separate categories.

Reading one: relative frequency of a bar = its height ÷ the sum of all bar heights.

A Pareto chart is a bar chart with the bars sorted from tallest to shortest, often with a cumulative-percentage line, so you can see which few categories account for most cases. Because it reorders the bars, it is valid only for nominal data. Sorting an ordinal variable by frequency destroys its order.

Bar chart vs histogram

Bar chart: categories, gaps between bars.
Histogram (week 3): a continuous numerical axis, bars touch.

How the exam asks it: “Compute the relative frequency of category B from this bar chart” and “is a Pareto chart appropriate here?”

2.3Pie charts

A pie chart shows shares of one whole. Each wedge's angle is its relative frequency times 360°. Every question is one of three conversions:

  • count → angle: angle = (f / n) × 360°
  • percentage → amount: amount = (p / 100) × total
  • angle → count: f = (angle / 360°) × n

Pies get hard to read with many small slices; group them into an explicit “Other”. Comparing two pies side by side is also weak — a bar chart of relative frequencies is clearer.

Worked example

A household budget of ₹48,000 is drawn as a pie. Rent has a 90° wedge; food is 30%.

Rent = 90/360 × 48,000 = ₹12,000.
Food = 0.30 × 48,000 = ₹14,400, wedge = 0.30 × 360 = 108°.

How the exam asks it: Pie percentages given, total given, “how much was spent on X?” or “how much more on X than Y?”

2.4Misleading charts: the area principle

The area principle: the area of ink must be proportional to the number it represents. Common violations:

  • Truncated axis — the bars start at, say, 80 instead of 0, so a 5% difference looks like a 3× difference.
  • Picture icons scaled in both width and height — doubling the value quadruples the area.
  • 3D and exploded pies — the front slices look bigger.

Round-off: percentages rounded one by one need not add to exactly 100, and angles need not add to exactly 360°. That alone does not make a chart wrong.

2.5Mode and median of a categorical variable

Mode = the category with the highest frequency. It works for nominal and ordinal data. There can be two (bimodal) or more.

Median = the middle case once the data is put in order. It needs an order, so it exists only for ordinal data. To find it, use the cumulative frequency: the median is the category containing case number (n + 1) / 2.

The mean does not exist for categorical data.

Worked example

Shirt sizes: S 12, M 30, L 25, XL 8, so n = 75.

Mode = M (30).
Median position = (75 + 1)/2 = 38th. Cumulative: S 12, M 42 — the 38th shirt is an M, so median = M.

Recap — read this the night before

  • Relative frequency — f / n; sums to 1; use it to compare groups of different size
  • Pie — angle = f/n × 360°; amount = % × total
  • Bar chart — gaps between bars; rel. freq = bar / sum of bars
  • Pareto — sorted bar chart, nominal only
  • Area principle — ink ∝ value; truncated axes and 2-D icons break it
  • Mode — any categorical variable
  • Median — ordinal only, via cumulative frequency

Traps that cost marks

  1. Pareto on ordinal data is wrong. Sorting S/M/L/XL by frequency destroys the order that makes the variable ordinal.
  2. A truncated baseline is an area-principle violation, not a style choice. It is the answer to “what is misleading about this chart?”
  3. Median is undefined for nominal data. Mode is the only centre a nominal variable has.
  4. Bars touch in a histogram, not in a bar chart.
  5. Individually rounded percentages need not sum to 100. An option claiming they must is false.
  6. Carry the fraction, not the rounded percentage. Rounding 22.5% to 23% before multiplying moves a pie angle by almost 2°.

W3

Central tendency & dispersion

0/4 learned · 41 marks

Week overview

Week 3 describes one numerical variable, and it carries the most marks in Stat 1. You summarise a list of numbers by its centre (mean, median, mode) and its spread (range, variance, standard deviation, interquartile range).

Expect to compute these from raw data, to work backwards from a given mean to a missing value, to merge two groups' means, and — the single most tested idea — to say what happens to each summary when every value is transformed by y = a·x + b.

After this week you can:

  • Compute mean, median and mode, and say which one resists outliers
  • Use Σx = n·x̄ to find missing values, correct a misrecorded value, and combine groups
  • Compute variance and SD for a sample and for a population
  • Find percentiles, quartiles and the IQR, and flag outliers
  • State the effect of y = a·x + b on every summary without recomputing

About 20 min to read · 4 practice problems at the end

3.1Tables, histograms and stem-and-leaf plots

A discrete variable with few values gets one row per value. A continuous variable is grouped into classes (about 5–20). The convention: a class includes its left end and excludes its right, so “30–40” contains 30 but not 40.

A histogram draws those classes as bars that touch, because the axis is continuous.

A stem-and-leaf plot keeps every actual value: the stem is all digits but the last, the leaf is the last digit. 42, 47, 51 → 4 | 2 7, 5 | 1.

3.2The mean, and the one identity that solves most questions

The mean is the sum divided by the count. Rearranged, it gives the identity behind a whole family of questions:

Σx = n · x̄

  • Missing value: the total must equal n × mean, so subtract the known values.
  • Misrecorded value: fix the total (remove the wrong value, add the right one), then divide again.
  • Combined mean: add the two totals and divide by the combined count. Never average the two means — that only works when the groups are the same size.

For a frequency table the mean is Σf·x / Σf. With grouped continuous classes, use class midpoints, and the result is only an approximation.

The mean is pulled hard by outliers.

Formulas

x̄ = Σx / n (sample), μ = Σx / N (population)
combined: x̄ = (n₁x̄₁ + n₂x̄₂) / (n₁ + n₂)

Worked example

Class A: 30 students, mean 60. Class B: 20 students, mean 70.

Totals: 30 × 60 = 1800 and 20 × 70 = 1400.
Combined mean = 3200 / 50 = 64 — not 65, which is the average of the two means.

How the exam asks it: “The mean of 10 values is 25; one value was wrongly recorded … find the correct mean”, or find a subgroup's mean from the overall mean.

3.3Median and mode

Median: sort the data first. If n is odd, take the value at position (n + 1)/2. If n is even, average the two middle values (positions n/2 and n/2 + 1).

The median ignores how extreme the extreme values are, so it is resistant to outliers. If a dataset is skewed or has outliers, the median is the better centre.

Mode: the most frequent value. A dataset may have none, one or several.

Worked example

Data: 3, 7, 8, 12, 50.

Mean = 80/5 = 16, but median = 8. Change 50 to 500 and the mean jumps to 106 while the median stays 8.

3.4Spread: range, variance and standard deviation

{3, 3, 3, 3, 3} and {1, 2, 3, 4, 5} have the same mean, median and mode but are clearly different. Spread measures capture that.

Range = max − min. It uses only two values, so a single outlier wrecks it.

Variance is the average squared distance from the mean. For a sample you divide by n − 1, for a population by N. When a question says “sample”, use n − 1.

Standard deviation = √variance, which puts the spread back in the original units.

A shortcut that saves time with awkward means: Σ(x − x̄)² = Σx² − n·x̄².

Formulas

s² = Σ(x − x̄)² / (n − 1)    σ² = Σ(x − μ)² / N
s = √s², σ = √σ²

Worked example

Sample 4, 8, 6, 10, 12. Mean 8.
Deviations −4, 0, −2, 2, 4 → squares 16, 0, 4, 4, 16 → sum 40.

Sample: s² = 40/4 = 10, s ≈ 3.16.
Population: σ² = 40/5 = 8, σ ≈ 2.83.

3.5Percentiles, quartiles, IQR and outliers

The p-th percentile is the value below which about p% of the data lies. The course method:

  1. Sort the data.
  2. Compute the rank n · p (p as a fraction, e.g. 0.25).
  3. If n·p is not a whole number, round it up and take that value.
  4. If n·p is a whole number, average that value and the next one.

Spreadsheets use a different rule (rank = p(n − 1) + 1, then interpolate), and some questions use position (n + 1)p. They can disagree, so use the method the question names; with none named, use the course method.

Quartiles: Q1 = 25th percentile, Q2 = median, Q3 = 75th percentile. IQR = Q3 − Q1, the spread of the middle half, and it is resistant to outliers.

Five-number summary: min, Q1, median, Q3, max — exactly what a box plot draws.

Outlier fences

lower fence = Q1 − 1.5 × IQR
upper fence = Q3 + 1.5 × IQR
Anything outside a fence is an outlier.

Worked example

Data 5, 7, 8, 10, 12, 15, 18, 40 (n = 8).

Q1: 8 × 0.25 = 2, a whole number → average of 2nd and 3rd = (7 + 8)/2 = 7.5.
Q3: 8 × 0.75 = 6 → average of 6th and 7th = (15 + 18)/2 = 16.5.
IQR = 9. Upper fence = 16.5 + 13.5 = 30, so 40 is an outlier.

3.6What y = a·x + b does to every summary

This is the most-tested idea of the week. Split the summaries into two kinds:

  • Location (mean, median, mode, any percentile, Q1, Q3) — these are positions, so they move exactly like a single value: multiply by a, then add b.
  • Spread (range, IQR, SD) — these are distances between values, so adding b cancels out. They scale by |a|. Variance is a squared distance, so it scales by a².
y = a·x + b
SummaryNew value
mean, median, mode, percentilesa × old + b
range, IQR, SD|a| × old
variancea² × old
Worked example

Mean 50, SD 6, and y = 3x − 10.

Mean = 3 × 50 − 10 = 140.
SD = 3 × 6 = 18 (the −10 does nothing).
Variance = 9 × 36 = 324.

How the exam asks it: Marks converted to a new scale, temperatures converted °C → °F (F = 1.8C + 32), a bonus added to every salary.

Recap — read this the night before

  • Σx = n·x̄ — missing value, corrected mean, combined mean
  • Combined mean — add totals, divide by total count; never average the averages
  • Median — sort first; resistant to outliers; the mean is not
  • Variance — sample ÷ (n − 1), population ÷ N; SD = √variance
  • Percentile — rank n·p: not whole → round up; whole → average with the next
  • IQR — Q3 − Q1; fences at Q1 − 1.5·IQR and Q3 + 1.5·IQR
  • y = ax + b — location: a·old + b; SD/IQR/range: |a|·old; variance: a²·old

Traps that cost marks

  1. n − 1 for a sample, n for a population. The most common silent error in the course.
  2. Adding a constant does not change spread. y = x + c leaves variance, SD and IQR exactly as they were.
  3. Scaling hits variance by a² but SD only by |a|. Squaring the SD change is the planted wrong option.
  4. Percentile rule: n·p whole → average that rank and the next; not whole → round up. Rounding to nearest is wrong.
  5. Never average two group means unless the groups are the same size.
  6. Sort before taking a median or percentile. The question will list the data unsorted on purpose.

Week overview

The tool depends on the variable types: two categorical → a contingency table; two numerical → a scatter plot, covariance and the correlation coefficient r; one numerical and one two-level categorical → the point bi-serial correlation. About 18 min to read · 4 practice problems at the end

4.1Two categorical variables: contingency tables

A contingency table has one variable's categories as rows and the other's as columns; each cell counts the cases with that combination. Add row totals, column totals and the grand total.

Three kinds of relative frequency come out of it. Read the question for which one it wants:

  • Joint: cell ÷ grand total — “what share of everyone attended and passed?”
  • Marginal: row or column total ÷ grand total — “what share passed?”
  • Conditional (row/column): cell ÷ its row (or column) total — “of those who attended, what share passed?”

Association rule: compare the row relative frequencies across rows. If they are about the same, there is no association; if they differ clearly, the variables are associated. A 100% stacked bar chart draws exactly this comparison.

Worked example
PassedFailedTotal
Attended602080
Did not154560
Total7565140

Pass rate: attended 60/80 = 0.75, did not 15/60 = 0.25. Very different → associated. But it is not proof that attending causes passing.

How the exam asks it: “What percentage of X are Y?” — the wording decides which total you divide by.

4.2Two numerical variables: scatter plots

Plot the explanatory variable on x and the response on y. Describe the cloud with D-C-V-O:

  • Direction — positive (rising) or negative (falling)
  • Curvature — straight-line or curved
  • Variation — tightly clustered or widely scattered
  • Outliers — points far from the rest

The numbers in this week measure only linear association. A perfect U-shaped pattern can have r = 0.

4.3Covariance

Covariance measures whether x and y move together. For each point multiply its x-deviation by its y-deviation: both above average or both below gives a positive product; one above and one below gives a negative one. Average those products.

The sign tells you the direction. The size is hard to read, because it is in mixed units (cm × kg) and changes when you change units.

Formula

Cov(x, y) = Σ(x − x̄)(y − ȳ) / (n − 1) for a sample, / N for a population

4.4The correlation coefficient r

Dividing covariance by both standard deviations removes the units, giving r:

r = Cov(x, y) / (sx · sy)

Properties to know cold:

  • r is always between −1 and +1. Near ±1 is a strong linear pattern; near 0 is weak or none.
  • r has no units, and swapping x and y does not change it.
  • Linear transformations: u = a·x + b, v = c·y + d gives r(u, v) = r(x, y) if a and c have the same sign, and −r(x, y) if they have opposite signs. Adding constants never matters.
  • If y is exactly a·x + b, then r = +1 (a > 0) or −1 (a < 0).
  • Correlation is not causation.

To compute r from raw data, build five columns — x, y, xy, x², y² — total them, and use the computational formula on the right.

Computational formula

r = [nΣxy − ΣxΣy] / √([nΣx² − (Σx)²] · [nΣy² − (Σy)²])

Worked example

x: 1, 2, 3, 4, 5   y: 2, 4, 5, 4, 5 (n = 5)

Σx = 15, Σy = 20, Σxy = 66, Σx² = 55, Σy² = 86.
Numerator = 5(66) − 15(20) = 30.
Denominator = √((275 − 225)(430 − 400)) = √(50 × 30) = √1500 ≈ 38.73.
r = 30 / 38.73 ≈ 0.775 — a fairly strong positive association.

How the exam asks it: “Compute r from this table”, and “if r(x, y) = 0.6, what is r(2x + 3, −5y + 1)?”

4.5Line of best fit, R², and the point bi-serial correlation

A line of best fit y = m·x + c summarises a linear scatter. The sign of the slope m matches the sign of r.

R² = r² is the share of the variation in y that the line explains. R² = 0.64 means 64% explained. Because it is squared, it carries no direction: r = 0.8 and r = −0.8 both give 0.64.

Point bi-serial correlation handles one numerical variable against one two-level categorical variable (pass/fail, male/female coded 0 and 1). It compares the numerical variable's mean in the two groups, scaled by its overall SD and by the group proportions p₀ and p₁. Swapping which group is coded 1 flips the sign, so only the size is meaningful.

Point bi-serial

rpb = (Ȳ₁ − Ȳ₀) / sY × √(p₀ · p₁)

Ȳ₀, Ȳ₁ = mean of the numerical variable in each group; p₀, p₁ = share of cases in each group; sY = SD of all the numerical values.

Recap — read this the night before

  • Joint / marginal / conditional — divide by grand total / by grand total / by the row or column total
  • Association — row relative frequencies differ across rows
  • Scatter — D-C-V-O; only linear association is measured
  • Covariance — sign = direction; size depends on units
  • r — Cov / (sxsy), in [−1, 1], unitless, symmetric
  • Transforms — r unchanged, except the sign flips if exactly one variable is multiplied by a negative number
  • R² — r², share of variation explained, no direction
  • Point bi-serial — one numerical vs one binary; sign depends on the coding

Traps that cost marks

  1. Association never licenses a causal claim, however strong r is.
  2. y = x + c has r = 1 exactly (and y = −x + c has r = −1). Recognise the shape instead of recomputing.
  3. R² has no direction. R² = 0.64 is consistent with r = +0.8 and with r = −0.8.
  4. The sign of rpb flips if you swap the 0/1 coding.
  5. Point bi-serial needs exactly one numerical and one binary variable.
  6. r = 0 does not mean no relationship — only no linear one.
  7. “Of those who …” means divide by that row's total, not the grand total.

1.4Strings

A string is a sequence of characters. Positions start at 0; negative positions count from the end, so s[-1] is the last character.

Slicing s[a:b] gives characters from a up to but not including b, so its length is b − a. Leave out a to start at the beginning, b to go to the end. A third number is the step: s[::2] takes every second character and s[::-1] reverses.

A slice past the end is clipped silently (s[2:100] is fine), but a single index past the end is an IndexError.

+ joins two strings; * with an int repeats. "a" + 1 is a TypeError. len(s) counts characters, spaces included. Strings cannot be changed in place: s[0] = "P" is an error.

Worked example

s[-1]    # 'n'
s[1:4]   # 'yth'
s[:2]    # 'py'
s[::-1]  # 'nohtyp'
s + "3"  # 'python3'

1.5f-strings, and how to solve any W1 question

An f-string drops values into text: f"{name} scored {m}". A format after a colon controls the look:

  • f"{7:4}" → "   7" — width 4, numbers right-aligned; the spaces count in len

Method for every W1 question: evaluate the innermost part first, write down its value and its type, then apply the next operator to that. Most wrong answers come from forgetting that a value is a string, or a float.

2.1Comparison operators

== (equal), != (not equal), <, <=, >, >= each produce a bool: True or False.

= assigns, == compares. Writing if x = 5: is a SyntaxError.

Strings compare letter by letter (dictionary order, using character codes). The first differing character decides. Uppercase letters come before lowercase, and digits before both. If one string is a prefix of the other, the shorter one is smaller.

Worked example
"apple" < "banana"   # True
"Zebra" < "apple"    # True  ('Z' before 'a')
"10" < "9"           # True  ('1' before '9')
"cat" < "catalog"    # True  (prefix)
10 < 9               # False (numbers)

2.2Chained comparisons

a < b < c means (a < b) and (b < c). It reads like maths: “b is between a and c”. The middle value is evaluated only once. It does not mean (a < b) < c.

Worked example

Read wrongly as (1 < 5) < 3 it would be True < 3 → 1 < 3 → True.

2.3bool is a kind of int

In Python True behaves as 1 and False as 0 in arithmetic. A comparison stays a bool until you do arithmetic on it; then it becomes an int.

  • True + True → 2 (int)
  • (3 > 1) * 10 → 10
  • type(3 > 1) → bool
  • True == 1 → True

So (a > 0) + (b > 0) + (c > 0) counts how many of a, b, c are positive.

2.4if / else and nested ifs

An if line ends with a colon, and the block under it is indented. Python runs the block only if the condition is True. An else block runs when it is False. Exactly one of the two runs.

3.1Logical operators and the full precedence order

not x flips a bool. x and y is True only if both are. x or y is True if at least one is.

When there are no brackets, Python applies operators in this order. The last three are where marks are lost: not before and, and before or.

Method: add brackets on paper according to precedence first, then reduce from the innermost bracket out.

Precedence, highest first

1. ( )
2. **
3. unary -
4. * / // %
5. + -
6. comparisons < <= == != >= >
7. not
8. and
9. or

Worked example

not True and False → (not True) and False → False
True or False and False → True or (False and False) → True
not 3 > 5 → not (3 > 5) → True

3.2elif chains vs separate ifs

In an if / elif / else chain Python checks the conditions top to bottom and runs only the first one that is True; the rest are skipped. The else runs only if none were True. Exactly one block runs (or none, if there is no else).

With separate ifs, every if is checked on its own. Several can run, or none.

So the two versions behave identically except for inputs that satisfy two or more conditions. To find where they differ, look for those inputs — that is the whole method.

Worked example
if x > 10: print("A")      if x > 10: print("A")
if x > 5:  print("B")      elif x > 5: print("B")

x = 12: left prints A B, right prints A.
x = 7: both print B. x = 3: both print nothing.

3.3What range does each branch really own?

In a chain, a later branch only runs if every earlier condition was False. So earlier conditions carve out part of each later one.

if x > 10 … elif x > 5 … else … means:

  • branch 1: x > 10
  • branch 2: 5 < x ≤ 10 (not just x > 5)
  • else: x ≤ 5

Write each branch's real range down, then test the boundary values (exactly the threshold, and one either side).

Order matters: if a chain checks m >= 50 before m >= 90, a 95 is caught by the first test and never reaches the second.

Counting whole numbers in a ≤ x ≤ b: b − a + 1.

3.4Truthiness: what counts as False

An if accepts any value, not just a bool. These are the only falsy values:

False   0   0.0   ""   []   ()   {}   None

Everything else is truthy, including "0", " ", "False", -1 and [0]. bool(x) shows you which.

3.5Short-circuit: and / or return an operand

Python stops evaluating as soon as the answer is known, and returns the operand it stopped at, not necessarily True or False:

  • a or b → the first truthy value; if none, the last value
  • a and b → the first falsy value; if none, the last value

Because it stops early, the right-hand side may never run at all: x != 0 and 10 / x > 1 is safe even when x is 0.

Worked example

0 or "x" → "x"
3 or 5 → 3
"" and 5 → ""
3 and 5 → 5
None or 0 → 0 (both falsy, so the last)

3.6isinstance, & and |, and choosing the correct snippet

isinstance(x, int) asks whether x is an int. Because bool is a kind of int, isinstance(True, int) is True, but isinstance(1, bool) is False.

& and | are bitwise operators, not and/or: 5 & 3 is 1. They don't short-circuit and they bind tighter than comparisons, so slow down when you see them.

“Which snippet is correct?” Don't read for style. Run every candidate on the nasty inputs: equal values, exactly the threshold, and a negative. The planted bug is almost always one of: separate ifs printing twice, an elif chain in the wrong order, > where >= was needed, or a missing else.

Recap — read this the night before

  • Precedence — arithmetic → comparisons → not → and → or
  • elif chain — first True branch only; separate ifs can all run
  • Where they differ — inputs satisfying two conditions at once
  • Branch ranges — earlier conditions carve out later ones; test boundaries ±1
  • Falsy — False, 0, 0.0, "", [], (), {}, None — nothing else
  • or / and — return the deciding operand, not a bool
  • isinstance — True is an int; 1 is not a bool

Traps that cost marks

  1. Precedence is not → and → or. not True and False is False; True or False and False is True.
  2. First true branch wins in an elif chain; separate ifs are all tested.
  3. Earlier conditions carve out later ones. Branch two of >10 / >5 owns 5 < x ≤ 10.
  4. "0", " ", "False", -1 and [0] are all truthy.
  5. or and and return an operand. 0 or "x" is "x", not True.
  6. isinstance(True, int) is True but isinstance(1, bool) is False.
  7. A chain with the wrong order (>= 50 before >= 90) silently puts everyone in the first band.

4.1while loops

A while loop has four parts. Get any one wrong and the loop either never runs, never stops, or is off by one:

  1. initialise the loop variable
  2. test the condition — if False, skip to after the loop
  3. run the body
  4. update the variable, then go back to step 2

If the condition is False the very first time, the body runs zero times.

After the loop ends, the variable holds the first value that failed the test — not the last value that passed.

Worked example
j = 1
while j < 20:
    j = j * 3
print(j)

j: 1 → 3 → 9 → 27. The test fails at 27, so it prints 27. The body ran 3 times.

4.2for loops and range()

for i in range(start, stop, step) gives i each value from start, moving by step, and stops before reaching stop.

  • range(5) → 0, 1, 2, 3, 4
  • range(1, 11) → 1 to 10 (ten values)
  • range(0, 10, 3) → 0, 3, 6, 9
  • range(10, 0, -3) → 10, 7, 4, 1
  • range(5, 1) → nothing (wrong direction for the default step 1)

After a for loop, i holds the last value it was given — unlike a while loop variable.

Counting values

count = ceil((stop − start) / step), or 0 if that is negative

range(1, 11): 10  ·  range(10, 0, −3): ceil(3.33) = 4

break and continue

break leaves the loop immediately.
continue skips the rest of this pass and goes to the next one.

4.3Accumulators

An accumulator is a variable that collects a result over the passes of a loop. Its starting value must be the one that changes nothing:

  • sum and count start at 0
  • product starts at 1 — starting it at 0 makes every answer 0
  • maximum starts at the first value (or a very small number)
  • a string being built starts at ""
Worked example
total = 0
for i in range(1, 6):
    total += i * i
print(total)   # 1+4+9+16+25 = 55

4.4The digit-extraction pattern

For a positive whole number n, n % 10 is its last digit and n // 10 drops that digit. Repeating both peels a number from the right until nothing is left. Many quiz questions use this one skeleton and change only the middle line:

while n > 0:
    d = n % 10      # last digit
    ...             # the line that changes
    n = n // 10     # drop it

4.5Trace tables: the only reliable method

Draw a table with one column per variable, plus a column for the condition. Write one row per pass. Stop on the row where the condition is first False.

  • Iteration count = the number of rows where the body ran. Count them.
  • Final value of a while variable = the value on the row where the test failed.
  • When checking candidate loops, compare three things: the first value, the last value and the count. The wrong options are each off by one in exactly one of these.
Worked example
n = 10; c = 0
while n > 1:
    n = n // 2
    c += 1

Ends with n = 1, c = 3.

4.6Simultaneous assignment and the two-pointer loop

a, b = b, a + b computes both right-hand values first using the old a and b, then assigns. Writing a = b then b = a + b on separate lines is different, because the second line sees the new a.

Two pointers: on a sorted list, i starts at the left end and j at the right. Compare a[i] + a[j] with the target: too big → j -= 1; too small → i += 1; equal → found. Loop while i < j; if the pointers meet, there is no pair and the function returns None/False.

Worked example
a, b = 0, 1
for _ in range(5):
    print(a)
    a, b = b, a + b

Prints 0 1 1 2 3 (Fibonacci).

Recap — read this the night before

  • while — init → test → body → update; may run 0 times
  • Final while value — the first value that fails the test
  • range(a, b, s) — excludes b; count = ceil((b − a)/s)
  • Final for value — the last value given
  • Accumulators — sum/count 0, product 1, string ""
  • Digits — d = n % 10, n = n // 10; reverse r = r*10 + d
  • a, b = b, a+b — uses the old values of both
  • Two pointers — too big → j −= 1, too small → i += 1, stop when they meet

Traps that cost marks

  1. A product started at 0 returns 0 for every input. Products start at 1.
  2. while n > 0 never runs on input 0, so the answer is the starting value.
  3. range(a, b) excludes b. range(1, 11) is ten values.
  4. A while variable ends on the first value that fails; a for variable ends on the last value given.
  5. a, b = b, a + b uses the old values of both.
  6. Off-by-one lives in three places: the first value, the last value, and the count.
  7. Forgetting the update (n = n // 10) makes the loop run forever — “infinite loop” is a legitimate option.
